# Portable document links

Disconnected exchange preserves structured BlockNote `href` and `url` links to pages in the same bound space. Absolute-path and relative-path links resolve to an exact local document identity at capture. Query strings and fragments are retained within bounded, validated suffixes. External HTTP(S), mail, telephone and fragment links remain unchanged; the exchange never fetches their destinations.

Signed bundles carry `octavo-doc:` document references, not a sender's space/page slugs. On import these become local identity links. The local redirect resolves the currently mapped page and slug, checks normal space/tenant access and draft visibility, and never redirects to an external origin. Published public pages remain accessible without a login under the normal publication policy. Missing, unapplied, conflicted or deleted targets return unavailable rather than guessing a replacement. Known dangling references retain their signed identity without blocking unrelated document application.

Forward and cyclic references require no placeholder documents. A reference to an entirely unknown identity or another lineage is held until the required same-lineage history arrives. Unrecognized relative paths, cross-space references and unsafe protocols fail closed.

For locally authored links, a source-document/path alias ledger records the exact target established during a successful capture. Later captures retain that identity after target rename or archival. Reusing the same path for another document holds export for explicit review instead of silently retargeting. The ledger has no cascading page foreign key and survives full-object archival/restoration. Binding and mapping scope checks still apply.

Capture does not rewrite live local page content or bypass collaborative-editor barriers. Consequently, opening a copied old literal URL directly can still return unavailable after a rename; exchange retains its original target identity, while imported identity links follow the new slug. Arbitrary prose, Markdown/code text and embedded diagram syntax are not rewritten as page links. Receivers without portable-link support may hold these revisions; upgrade participating sites before relying on this feature.

## Originating reader links
The ordinary reader view now projects already-captured source/path aliases into source-scoped resolver links without writing page content or touching active editor buffers. It does this before composition and independently for each embedded page, so aliases never inherit another source context. Click-time checks revalidate source and target permissions, original space/lineage and slug reuse. Renamed targets resolve to their current local slug; deleted, conflicted, moved or ambiguous targets remain unavailable. Source drafts cannot reveal target locations to anonymous readers.

This projection is deliberately limited to the ordinary reader view. Editor content, copied raw URLs, Markdown exports and other specialized render surfaces are not rewritten; old literal links there can still become stale. Only paths recorded during a successful exchange capture have stable historical identity. Never-captured links cannot be recovered by guessing.

Visitor-token limitation: the ordinary reader supports a revocable, space-scoped visitor cookie for published private pages, but these identity/source-link resolver routes currently require normal space access (membership or permitted public access). A visitor-only reader can open the original page yet receives 401/404 on a projected link. This is fail-closed, not guest-navigation parity. Any later alignment must validate the same-space visitor token on every click, preserve revocation/expiry, and require ordinary membership plus editing capability for both source and target drafts; a visitor token must never grant draft or cross-space access.
